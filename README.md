# Delay-induced network oscillations

MATLAB simulation code accompanying **Delay-induced network oscillations shape epileptic fast ripple activity in a computational model based on human epileptic tissue data**.

The simulator models recurrent Izhikevich spiking neurons, delayed synaptic transmission, refractory periods, and spike-timing-dependent plasticity (STDP). Time is discretized into 0.25 ms bins, with two membrane-integration half-steps per bin.

## Fixed input network state

Simulations start from a fixed network continuation state prepared during earlier experiments. For this study, that state is supplied as an external input rather than regenerated by the repository. Each batch run starts from an independent copy of the state, with selected parameters and a random seed applied before simulation.

The input MAT file must contain a scalar struct named `G`, including the network, neuronal variables, synaptic state, delayed-current and STDP buffers, prior activity histories, and auxiliary indexing structures. Network initialization generators are outside the scope of this release and may be added later. The fixed input state is sufficient to run the experiments in this release once supplied separately.

Scientific input data are intentionally absent from Git. They will be archived separately on Zenodo. See `data/README.md` for the input contract and the metadata to accompany that archive. No data DOI has been assigned in this repository yet.

## Input MAT file: `data/net_config_G_only.mat`

`net_config_G_only.mat` denotes a saved network state, not a table of measured spike times or a file of model parameters alone. It must contain a top-level MATLAB variable named **`G`**, stored as a scalar struct. The filename and directory are arbitrary: pass the actual relative or absolute path to the runner. The batch entry point loads only `G`; other top-level variables, if present, are ignored.

The example file is not included in Git. Obtain the fixed state from the separate data archive when available, or use an independently prepared state satisfying the same contract. Reproducing this study requires the study's specific archived state, not just any structurally valid network.

| Fields in `G` | Required structure and role |
| --- | --- |
| `N`, `Ne`, `D` | Positive integer scalars: total neurons, excitatory neurons, and maximum axonal delay in 0.25 ms bins; `Ne <= N`, `D <= 4000`. Excitatory neurons occupy indices `1:Ne`. |
| `t1`, `t2` | Positive integer continuation-clock values; `t1` is the next second within a minute (`1:60`, or boundary value `61`), and `t2` is the minute counter. |
| `lr`, `esr`, `sm` | Scalar model parameters: `0 <= lr <= 4000`, `0 <= esr <= 4`, `sm > 0`. Batch configurations can override them. |
| `v`, `u`, `a`, `d`, `ref`, `ref_duration` | Numeric `N x 1` neuron-state/parameter vectors. Refractory counters/durations are nonnegative integers in simulation bins. |
| `s`, `sd`, `delays`, `delays_dend` | Numeric `N x N` matrices for synaptic weights, derivatives and delay/index information. Rows identify presynaptic neurons and columns postsynaptic neurons. |
| `s_ind` | One-based MATLAB linear indices of synapses updated at the end of each second. |
| `I`, `sI_Tmax`, `sI_template` | Current buffer `I`: `N x sI_Tmax`; positive integer width `sI_Tmax`; numeric template matrix with `sI_Tmax` columns. Active `delays_dend` entries select valid template rows. |
| `STDP` | Numeric trace buffer with `Ne` rows and at least `4001 + D` columns. |
| `firings` | Nonempty numeric two-column array `[time_bin, neuron_id]`, sorted by time, beginning with sentinel `[-D, 0]`; subsequent neuron IDs are integers in `1:N`. |
| `delays_ref`, `pre`, `aux` | Precomputed indexing structures: `delays_ref` is an `N x D` cell array of target-neuron indices; `pre` and `aux` contain at least `Ne` cells with matching per-neuron lengths. These must agree with the supplied connectivity and delay buffers. |
| `A`, `s_mean` | Equal-length column vectors of prior per-second activity and mean-weight histories, or empty arrays. |
| `Adj`, `r` | Required when recording is enabled: numeric/logical `N x N` adjacency and positive numeric `N x 1` distances. In this mode `delays` must contain nonnegative integer bins. |
| `rng_state` or `rand_state` | Required for direct simulator calls: a valid `mt19937ar` state vector or a scalar integer seed in the uint32 range. Batch runs instead apply each configured seed. |

Numeric state values must be real and finite. Auxiliary indices use MATLAB's one-based indexing. The repository validates the supplied state but does not construct missing buffers or indexing fields. Structural checks do not establish that an independently prepared state is scientifically equivalent to the study's fixed state.

Inspect and validate the file before running simulations:

```matlab
input_file = 'data/net_config_G_only.mat';
whos('-file', input_file);
loaded = load(input_file, 'G');
assert(isfield(loaded, 'G'), 'Input MAT file must contain variable G.');
validate_network_state(loaded.G, true); % Check requirements for recorded runs.
```

For direct continuation, `restore_simulation_rng(loaded.G)` additionally checks the RNG representation. See [the detailed input contract](data/README.md) for index/buffer consistency and external-data metadata.

## Repository layout

- `runSim4quart.m`: continuation simulator.
- `run_batch_runSim4quart.m`: independent runs over a parameter/seed grid.
- `run_experiment_batch_cli.m`: MATLAB batch entry point.
- `validate_network_state.m`, `restore_simulation_rng.m`: state validation and RNG restoration.
- `motif_index.m`: motif counts, ratios, and optional surrogate statistics.
- `configs/`: runnable configuration functions.
- `tests/`: static checks, small technical regression tests, and validation using an external network state.
- `submit_runSim4quart.sh`: main SLURM wrapper; `submit_runSim4quart_batch.sh` is a compatibility alias.
- `submit_validation.sh`: short validation job using an external input state.
- `data/`: documentation of external inputs, without scientific MAT files.

This release does not include the upstream preparation of the scientific network state or the complete downstream experimental signal-processing and figure-generation pipeline.

## Requirements

MATLAB is required. The revised code passed short validation on 2026-10-08 using MATLAB R2024b Update 4 on Linux. This is a tested environment, not a verified minimum MATLAB version.

SLURM and an environment module system are required only for the supplied submission wrappers. Configure `MATLAB_MODULE` to the module available on your system and select an appropriate partition, wall time, and memory allocation. The module and resource defaults in the wrappers are examples from the development environment. Static checks use Python 3's standard library and Git; Bash enables additional shell syntax checks. No C/C++ binaries are required by this MATLAB pipeline.

## Quick validation

Place the repository and the external scientific input MAT in your working environment. From the repository root, run static checks:

```bash
python3 tests/check_repository_static.py
```

Run the full short validation wherever MATLAB is available:

```bash
matlab -batch "addpath('tests'); run_task_validation('data/net_config_G_only.mat')"
```

The function name `run_task_validation` is retained for compatibility; it does not require a particular cluster. Replace the example input path with your actual file. Validation runs small regression tests and a one-second batch using the input state's model parameters. It writes outputs under `validation_results/`; the input MAT is not overwritten.

For SLURM submission, choose your site's module and partition:

```bash
mkdir -p logs
MATLAB_MODULE=YOUR_MATLAB_MODULE sbatch --export=ALL --partition=YOUR_PARTITION submit_validation.sh data/net_config_G_only.mat
```

Keep complete stdout/stderr logs. SLURM validation logs are `logs/izh_validation_JOBID.out` and `.err`. Successful completion is reported at the end of stdout.

The technical tests can also run without scientific data in MATLAB:

```matlab
addpath('tests');
run_unit_tests;
```

These checks assess implementation and bookkeeping, not scientific validity, convergence, or reproduction of all manuscript figures. See `README_REPRODUCIBILITY.md` for their scope.

## Run an example batch

```bash
mkdir -p logs
MATLAB_MODULE=YOUR_MATLAB_MODULE sbatch --export=ALL --partition=YOUR_PARTITION submit_runSim4quart.sh data/net_config_G_only.mat config_publication_example
```

`config_publication_example` is a two-second functional example, not the full manuscript experiment. `config_grid_lr_esr` defines a longer parameter sweep. Adapt wall time and memory when submitting production runs. For example, to override both the module and time limit:

```bash
MATLAB_MODULE=YOUR_MATLAB_MODULE sbatch --export=ALL --partition=YOUR_PARTITION --time=00:30:00 submit_validation.sh data/net_config_G_only.mat
```

For direct execution in a MATLAB environment (use an allocated compute node when required by your cluster policy):

```bash
matlab -batch "run_experiment_batch_cli('data/net_config_G_only.mat','config_publication_example')"
```

## Outputs and stopping

Each successful simulator call produces a MAT file, plus batch-level MAT/CSV summaries. `finished` means the simulator returned without an exception; `completed_requested_duration` separately states whether the requested duration was reached. `stop_reason` distinguishes normal completion, runaway thresholds, and errors. These diagnostics are stored in each successful run's `run_metadata`, even if full states or recordings are disabled.

Dense recordings contain exactly 4000 samples per completed second, including early termination. `A_mean`, `A_max`, and `s_mean_mean` describe only the new run segment; prior histories remain in the saved `G`. The original runaway thresholds still consider recent history, including the supplied state's history.

`config.rec` controls recordings. `config.plot`, default false, independently enables raster plotting. Undefined motif ratios and surrogate Z scores are represented by NaN. Run-specific exceptions are saved in `*_ERROR.mat`; the CLI saves the batch summary and then exits with failure if any run failed.

Outputs with matching names are overwritten; use a separate output directory for each experiment. See `RUNNING_BATCH_EXPERIMENTS.md` for configuration and replay details.
